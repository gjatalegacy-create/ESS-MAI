# Security policy

ESS-MAI is experimental research software and is not represented as a production security system.

## Private reporting

Do not open a public issue for a finding that includes an exploitable vulnerability, credential, private key, personal data, or other sensitive material. Send a concise report to [gjata@legacy.al](mailto:gjata@legacy.al) with:

- the affected public path and version or commit;
- the environment and exact reproduction steps;
- expected and observed behavior;
- potential impact;
- a minimal proof of concept when it can be shared safely.

Non-sensitive build failures, documentation errors, and research counterexamples should use the public issue templates.

## Scope boundary

This policy covers files publicly present in this repository. The full private ESS-MAI v1.8.9 workspace is not included in the public POC collection and should not be inferred from, requested through, or attached to a report.

Publication of a POC, passing tests, or a fail-closed design goal does not constitute an independent security certification.
